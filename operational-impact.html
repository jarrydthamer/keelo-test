How the ledger works

  1. 01

    Intent

    A person or model proposes an action. The request specifies the result it is trying to achieve.

  2. 02

    Ingress

    The request enters a controlled path with the context needed to identify the organisation, actor and requested operation.

  3. 03

    Authority boundary

    KƎƎLO™ checks policy, current delegation and operating state before a governed write. Missing or invalid authority prevents the action from proceeding.

  4. 04

    Effect

    An authorised operation crosses a controlled adapter into the target system. Duplicate protection applies within the tested execution and receiver contract.

  5. 05

    Receipt

    The receipt records the outcome available to KƎƎLO™ and ties it to the authority and evidence behind the request.

  6. 06

    Verification

    The system checks the observed result against the intended effect. An uncertain result remains visible for review.

  7. 07

    Reconciliation

    The system compares the request, receipt and observed result. Any unresolved work stays open until it can be accounted for.
