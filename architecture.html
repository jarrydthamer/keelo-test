Core Architecture

Keelo separates neutral governance primitives from orchestration, external integrations and organisation-specific context. This keeps the core deterministic and the integration boundary explicit.

Core

Neutral governance primitives define the invariant semantics Keelo relies on.

  • Identity and authority
  • State and transitions
  • Evidence references
  • Obligations and decisions

Runtime

The runtime orchestrates governed operations and advances state using deterministic transition rules.

  • Command orchestration
  • Concurrency control
  • Retries and idempotency
  • Execution receipts

Adapter

Adapters are the only boundary through which Keelo communicates with source and execution systems.

  • Typed interfaces
  • Input normalisation
  • Output verification
  • Failure isolation

Organisation Instance

Each organisation operates inside an isolated context containing its policies, state and integration bindings.

  • Tenant isolation
  • Organisation policies
  • Scoped credentials
  • Independent state

Director and Forge

Director

Coordinates operating priorities and delegates work within the organisation’s policies and authority limits.

Forge

Defines bounded capabilities and executes authorised actions through adapters. Each governed outcome produces a durable execution receipt.

System Boundaries

Keelo does not become the business systems it governs. It preserves the governance record and coordinates through adapters, leaving raw source data and domain ownership where they belong.

No raw-source ingestion by default

Keelo references and normalises only the evidence required for governance rather than duplicating entire source datasets.

  • Minimal evidence footprint
  • Reference over replication
  • Explicit retention rules

Does not replace source systems

CRM, finance, HR, project and operational systems remain authoritative for their native domains.

  • Domain ownership preserved
  • Source-of-truth boundaries
  • Adapter contracts

No organisation business logic in Core

Organisation-specific rules belong in scoped configuration and policies, not in neutral Keelo primitives.

  • Portable core
  • Configurable policy
  • Reduced coupling

Adapter-only integration boundary

All external effects cross typed adapters so they can be verified, retried, isolated and audited.

  • Controlled side effects
  • Integration observability
  • Failure containment

By Design

Keelo is intentionally conservative at its core: persistent, traceable, deterministic and isolated by organisation. Those constraints make it safe to coordinate systems that were never designed to share governance.

Persistent state

Authoritative state survives processes, sessions and system restarts.

  • Durable storage
  • Explicit lifecycle
  • Replayable history

Evidence lineage

Inputs, decisions, approvals and outputs remain connected by references.

  • Provenance chain
  • Tamper-evident records
  • Source attribution

Deterministic execution

Equivalent commands against equivalent state resolve through the same governed path.

  • Stable transition rules
  • Idempotency controls
  • Predictable failure modes

Isolation & concurrency

Organisation boundaries and concurrent updates are treated as first-class correctness concerns.

  • Organisation isolation
  • Optimistic/explicit locking
  • Conflict detection
